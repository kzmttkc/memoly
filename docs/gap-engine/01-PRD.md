# PRD — 就業規則AI（買収前提の核）

最終更新: 2026-08-29
対象ユーザー: 従業員 10〜100 人の中小の経営者・総務、および顧問先を抱える1人社労士
成功の定義: 「自社ファイルを置いて穴を1枚にし、その前提で相談が続く」のデファクトになること

## 1. 問題

中小企業の就業規則は、作ったあとに読まれない。法改正で穴が開き、現場運用と条文がずれる。汎用AIに貼ると毎回前提が消え、必須記載が落ち、法令が古いまま残る。社労士に出すと15〜30万円と数週間がかかる。知りたいのは「今のファイルに何が書いてあって、何が書いてないか」である。

## 2. 製品原則

1. 登録の前に価値を出す。ずれ1枚はログイン不要。
2. 不足を断定しない。ファイルから読めなかったことを言う。適法性の確定はしない。
3. 会社を覚える。同じファイルを再貼付させない。
4. 社労士の代わりを名乗らない。渡すメモまでが仕事。
5. データは会社単位で分離し、学習に使わない。
6. 個人情報・要配慮情報・マイナンバーを記憶に残さない。
7. 完成品・届出・電子申請を出さない。

## 3. 核ジョブ（この順でしか作らない）

| ID | ジョブ | 成功条件 |
|---|---|---|
| J1 | ファイルを置く | PDF / docx / txt / 貼付が 30 秒以内に受理され、未読ページが残る |
| J2 | ずれ1枚を見る | 書いてある / 運用なし / 触れていない が優先度つきで1画面になる |
| J3 | 残す | ユーザー操作後にだけ会社書類へ移る。それまでサーバに書かない |
| J4 | 会社記憶で相談する | 置いた条文を引用し、書いてない論点は一般情報＋専門家確認と返す |
| J5 | 社労士メモを出す | 基本情報・整備済み規程・期限・運用・論点をコピー可能な1枚にする |
| J6 | 欠落を匿名集計する | 業種×人数帯×欠け項目の頻度だけ残す。本文も氏名も残さない |

## 4. 明示的にやらないこと

- 入退社・給与・勤怠・電子申請の本体
- 届出用の完成就業規則
- 人事評価の自動化
- 「不足している＝違法」という判定
- 従業員の傷病・ハラスメント相談の詳細を長期記憶すること
- 姉妹サービス（uitruth 等）への導線を労務画面に置くこと

## 5. ペルソナと最初の成功

### P1 総務が1人の飲食店（従業員 18 名）
最初の成功: 既存PDFを置いて、カスハラの文言がないことと年5日の運用がないことを1枚で見る。10月1日までに何を専門家へ渡すか決める。

### P2 建設業 30 名、36協定が怪しい
最初の成功: 上限規制と特別条項の記述の有無が1枚に出る。相談で「先に36協定」と返る。

### P3 1人社労士、顧問先 12 社
最初の成功: 顧問先を切り替えてもデータが混ざらない。面談前にメモを受け取る。

## 6. 受け入れの数字（プロダクト）

- 登録前のずれ1枚生成: p95 45 秒以内（8MB、テキスト抽出可能なPDF）
- 未読ページ率を画面に出す。0ページ読めた場合は1枚を出さず再提出を促す
- 絶対的記載事項7項目の再現率（ゴールドセット）≥ 0.90
- 「触れていない」の適合率 ≥ 0.80（誤って「ない」と言わない）
- 相談回答の 100% に「一般的な情報提供であり個別の法的助言ではない」を付ける
- 届出用Wordの自動生成ボタンを置かない

## 8. 法務コピー（画面に固定する文言）

出力フッター（必須）:

> この1枚は、置いたファイルから読み取れた範囲の整理です。不足の断定でも、適法性の保証でもありません。届出用の完成書類ではありません。最終判断は必要に応じて専門家へ確認してください。

相談回答の末尾（必須）:

> 一般的な情報提供です。個別の法的助言、書類作成代行、届出の代行ではありません。
