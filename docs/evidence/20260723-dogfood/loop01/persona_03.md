**ヒーロー第一ビュー**: 「会社のことを覚えて、労務の調べ物を減らすAI」／サブ「『この残業、うちは大丈夫？』を毎回ゼロから調べていませんか」。

**スクロールで解決する差別化資産（いずれも良質）**:
1. **「汎用AIとの違いは覚えているか」左右比較** — 前提を聞き返す汎用AI vs 前提から答える番頭。明快。
2. **比較表（番頭／SmartHR／オフィスステーション／汎用AIチャット）** — この persona に最も刺さる資産。
   - 主な役割: 番頭=会社の規程・前提を覚えて自社前提で答える / SmartHR=手続き電子化＋従業員DB。
   - 自社規程を覚えた回答: 番頭=**中心機能** / SmartHR=**主目的ではない**（＝記憶の深さの差別化）。
   - 導入までの時間: 番頭=**登録から数分で初回回答** / SmartHR=初期設定・従業員登録を経て。
   - 手続き電子申請・給与: 番頭=**非対応（下書きまで）** / SmartHR=得意。
   - 明記: 「番頭は手続きシステムの代替ではないため、**SmartHRやオフィスステーションと併用できます**」。→ 併用可否の疑問に**◎で回答**。
3. **セキュリティ節** が厚い（行レベル分離／HTTPS・TLS／Supabase／AI学習に使わない／削除権）。重複投資を警戒する管理部長の「預けて大丈夫か」に正面から答える構成。

## (D) チャット回答の説得力（自社アカウントで実測）

質問: 「SmartHRのような人事労務システムを既に使っています。番頭を併用する意味は何ですか。就業規則の内容について自社固有の相談ができるのが違いですか」

回答（要旨・実測）:
- 「違いは"自社固有の内容を前提にした相談ができるかどうか"にあります」と**結論を先に肯定**。
- SmartHRが得意（手続き電子申請・給与・勤怠・法改正の自動対応＝どの会社も共通の手続き）／番頭が得意（"うちの就業規則ではどうなっている"の解釈相談・過去の社内判断を踏まえた継続助言・規程と法令の食い違いの気づき・担当交代でも引き継げる記憶）を**箇条書きで対比**。
- 「SmartHR=手続きを動かすシステム、番頭=自社ルールを前提に考える相談相手、という役割分担」と一文で要約。
- **正直さ**: 「現時点ではAcme Japan K.K.の就業規則・ルール・過去の相談がまだ登録されていません。登録が進むほど"うちの会社の場合は"で答えられます」と空状態を明示し、条文登録を促す。
- 回答後に **記憶に保存／期限を作る／社労士に渡すメモを作る／規程ドラフト下書き** の導線＋「この方針を会社の記憶に残しますか？」の記憶化プロンプト（＝"覚える"を実演）。

**評価**: 比較検討者が「乗り換えでなく併用、役割が別」と判断するのに十分な説得力。LP比較表と一貫。◎
