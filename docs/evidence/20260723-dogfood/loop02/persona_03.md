   - 締め: 「番頭は手続きシステムの代替ではないため、**SmartHRやオフィスステーションと併用できます**。」
2. **専用ブロック「すでにSmartHRなどをお使いの方へ」**（Loop1で追加された箇所）
   - 「番頭は既存の手続きシステムを置き換えません。従業員情報や規程を、番頭に**すべて入れ直す必要はありません**。相談したい範囲の規程の要点だけを対話で覚えさせれば、自社の前提に沿った回答が得られます。手続き・給与関連はこれまでのツールのまま、番頭は『自社ルールの相談窓口』を1つ足す位置づけです。」
3. **セキュリティ節**: 会社ごと行レベル分離（RLS）・TLS暗号化・Supabase・「AI学習に使いません」・アカウント削除で全消去。

→ **この時点で二重入力の不安はLPだけで実質解消される作りになっている。**

- 5問答えただけで具体的な成果物が返る＝**登録直後の空白がない**。比較モードの「入れて何が返るのか」への即答になっている。

### C-5. チャット質問（核心・証拠: `evidence_p03/04_chat_answer_smarthr.png`）
チャット上部に前提バッジ「製造業・従業員100人以上・36協定あり・就業規則あり・固定残業代なし」を表示。ペルソナの質問をそのまま投げた:

> 「SmartHRと勤怠システムを使っています。番頭は何を置き換えず、何を足すのですか。規程は全部入れ直しですか」

`/api/company/chat` **200**、相談カウント 20→19（正常消費）。回答は質問の3つの下位問いに**見出しで対応**した構造（全文は証拠画像）:

- **何を置き換えない**: 「SmartHRや勤怠システムは『データを保存・処理するシステム』。番頭はそれらを置き換えません。SmartHR＝入退社手続き/雇用契約書/社員マスタ、勤怠＝打刻/集計/残業時間は**そのまま使い続ける**。」
- **何を足す**: 「番頭は『社内の制度・ルール・過去の判断を覚えて相談に答える記憶と知恵の層』。判断の補助／継続的な記憶／法改正時の注意喚起。事実データを扱うSmartHR・勤怠に対し、番頭は"どう判断・運用するかを支える"**役割分担**。」
- **規程は全部入れ直しか**: 「『入れ直す』より『番頭に読み込ませる』作業。SmartHR登録済みでも自動参照はできないので、**優先度の高い規程から順に**（就業規則→賃金規程→36協定→育児介護）、**抜粋でも可**。」
- 末尾に「【根拠】参考情報（要確認）」＝自社規程未登録のため一般整理である旨を正直に明示。

→ **LP（比較表＋専用ブロック）とチャット回答が完全整合**。ペルソナの中核不安（併用の要否・二重入力）に直接答えている。
