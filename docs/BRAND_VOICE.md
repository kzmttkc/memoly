## 1. 声の人格

番頭（ばんとう）＝店のことを隅々まで覚えている、老舗の番頭さん。

- 記憶力がよく、控えめで、実務に強い。主役は店主（顧客）で、番頭は支える側。
- 煽らない。不安を増幅して売らない。困りごとには「こう整理できます」と静かに返す。
- 断定しない領域を知っている。法律の最終判断は専門家、という線引きを自分から言う。
- 距離感は「取引先の担当者」。友達口調にしない。かしこまりすぎもしない。

## 2. 使う語 / 使わない語

### 使う語（番頭の語彙）

| 語 | 使い方の例 |
|---|---|
| 覚える／覚えている | 「自社の規程を覚えて」「番頭が覚えているので」 |
| 前提 | 「前提を説明し直さずに」「自社の前提で答えます」 |
| 続き（昨日の続き） | 「二度目の相談は、昨日の続きから始まります」 |
| 調べ物 | 「日々の調べ物を減らします」（「業務効率化」より具体） |
| 整理 | 「論点を一緒に整理します」（「解決」と言い切らない） |
| 下書き | 「規程ドラフトの下書き」（成果物は下書き止まり） |
| 自社の場合 | 「うちの場合は」と聞く顧客の言葉をそのまま使う |
| 手間・手が止まる | 「調べ直すと手が止まります」（顧客の体感語） |

### 使わない語

| 分類 | 語 | 理由 |

| Phase1コンプラ禁止 | 社労士監修／AI社労士／法的精度○点／精度保証／完全対応の保証 | 資格法・誇大表示。例外なし |

| 禁止語（出荷ゲート） | とても／皆さん／みなさん／——（長ダッシュ）／マークダウン太字(**) | kizuna_gates HARD ルール |
| 命令調 | 「〜してください」の連発／「〜すべきだ」の言い切り | 「〜できます」「〜が安心です」で置く |
| AI業界語 | LLM／プロンプト／ハルシネーション | 顧客（総務担当）の語彙で書く |

## 3. 「昨日の続き」の使い所

シグネチャは希釈すると死ぬ。使う場面を絞る。

- 使う: 再訪・継続の文脈に限る。ヒーローH1（A変種）、signup直前の後押し、メール件名・再訪リマインド、OG画像。
  - 実例（本番LP）: 「二度目の相談は、昨日の続きから始まります」（app/business/_components/HeroCopy.tsx）
  - 実例（signup）: 「一度覚えた前提は説明し直す必要がありません。二度目の相談は、昨日の続きから始まります。」
- 使わない: 初見向けの製品説明の一文目（初見にはカテゴリ即解「会社のことを覚えて、労務の調べ物を減らすAI」が先）。機能一覧・料金・免責などの事務的文脈。
- 頻度: 1ページ・1メールにつき1回まで。言い換え輪番（実例: /roumu/[slug] の CTA_SUBCOPY「二度目からは、話が早い」）で反復を避ける。

## 4. 敬体規則

- 全文を敬体（です・ます調）で統一する。常体の言い切り（〜だ／である／した）を地の文に混ぜない。
- 例外: 就業規則・規程・法令の条文引用と規定例は、慣習どおり常体のままでよい。
  - 実例（/roumu/kasuhara-gimuka-2026）: 「第◯条（相談体制） 前条の迷惑行為に関する相談に応じるため、会社は相談窓口を設け、従業員に周知する。」
- 語尾の圧: 「〜しましょう」より「〜できます」「〜が安心です」。読者を動かすのは命令でなく見通し。
- 一人称は出さない（ステルス運用・Tak人格の漏出禁止）。主語は「番頭」か省略。

## 5. やさしい日本語の原則（I04）

多言語対応の代わりに、総務担当が疲れていても読める日本語を標準にする。

1. 一文を短くする。目安は50字。読点で3つ以上つなげたら2文に割る。
2. 漢語より和語を選ぶ。「利用する→使う」「保管する→預かる・しまっておく」「実施する→行う」。
3. 専門用語には説明を添える。初出の用語は（ ）で短く言い換えるか、直後の一文で説明する。
   例: 「分離保管（会社ごとに分けて保管すること）」「36協定（残業をさせるために必要な労使の取り決め）」
4. 二重否定を使わない。「流用されないことはありません」型は書き直す。
5. 抽象語で終わらせない。「適切に対応します」ではなく「何を・いつ・どうするか」まで書く。

模範例: lib/faq.ts の次の2問は、この原則で書き直した実例（2026-07-23）。新しいFAQ・UI文言はこのトーンに合わせる。

- 「登録した規程データを他社の回答に使われることはありますか」
- 「規程の内容と現場の実際の運用が違う場合、どう扱えますか」

## 6. チャネル別の音量

- LP（/business, /roumu/*）: 顧客の状況描写から入る。実例（B変種アイブロー）: 「『この残業、うちは大丈夫？』を毎回ゼロから調べていませんか」。痛みは名指すが、合法/違法の断定はしない。
- FAQ: 質問に一文目で直答する（「ありません。」「できます。」）。理由と条件はその後ろ。
- メール: 件名は用件だけ（実例: 「今週の労務ダイジェスト｜番頭」）。本文は最短で、免責と配信停止導線を必ず持つ。署名は「番頭（banto-roumu.com）／support@banto-roumu.com」で固定し、他ドメインを出さない（G11）。
- チャットUI・アプリ内: 「わからない」を言ってよい。わからないときは次アクション（専門家に渡すメモ）を添える。
- X・note: 疑問形＋口語で入ってよいが、§2の禁止語と誇大は同じ基準。製品が特定できる画像を必ず添付する。

## 7. 免責の定型（変えずに使う）
